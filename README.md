# 정비 전산 결제 연동 예제

정비 전산에서 [담기]를 누르면 토스 POS 장바구니에 품목이 들어가고 결제 화면이 열리며, 결제가 끝나면 정비 전산에 결제완료가 반영되는 흐름을 보여 주는 예제입니다.

## 개발 요청 범위

이 저장소는 개발 요청의 참고 예제입니다.

만들어 주실 것은 세 가지입니다.

1. **토스 POS 결제 플러그인**: `plugin/` 이 그 예제입니다. 서버와 주고받는 메시지는 [`PROTOCOL.md`](PROTOCOL.md) 를 따릅니다.
2. **정비 전산 서버 쪽 연동**: 플러그인 접속 창구(매장 토큰 인증), [담기] 명령 전달·보관·재전송, 결제 반영, 토스 결제 웹훅 수신과 주문 조회. `server/` 가 같은 규약으로 만든 참고 구현입니다.
3. **정비 전산 화면**: [담기] 버튼, 상태 표시(결제대기·결제완료·취소(환불)), 다시 요청.

- **읽는 순서**: 이 README → [`docs/`](docs) 의 연동 방식·기술 정보 → [`PROTOCOL.md`](PROTOCOL.md) → `plugin/README.md` → `plugin/src/payment/` (핵심은 `bridge.ts`) → `server/README.md` → `server/src/`.

토스 개발자센터 등록(POS 플러그인·Open API 앱), ACL·웹훅 설정, 개발 배포와 테스트, 검수·배포는 **요청 측에서 진행합니다.** 서버에 넣을 웹훅 시크릿과 Open API 키는 요청 측에서 전달합니다. 시험을 위해 아래를 전달해 주시고, 테스트 단말 시험에 함께 참여해 주시면 됩니다.

1. 플러그인 소스와 `npm run release` 로 만든 zip
2. 시험용 서버 주소(https). 시험 기간 동안 계속 켜 두어 주십시오
3. 시험 매장 토큰
4. 시험용 정비 전산 화면 계정([담기]와 상태 변화를 요청 측에서 직접 확인)
5. 요청 측이 전달한 웹훅 시크릿과 Open API 키를 시험 서버에 넣기 아래 "실제 토스 POS로 해 보기"는 개발 중에 직접 시험해 보실 때의 절차입니다.

실제 서버 주소, 납품 형태처럼 이 저장소에 없는 사항은 개발 요청서에서 따로 정합니다.

## 구성

| 폴더·파일 | 내용 |
|---|---|
| `plugin/` | 토스 POS 결제 플러그인(iframe 탭 앱, React + Vite + TypeScript). 정비 전산 서버에 접속해 [담기] 명령을 받아 POS 장바구니에 넣고 결제 화면을 엽니다 |
| `server/` | 정비 전산 서버 역할 예제(Node.js). POS 접속 창구, [담기] 명령 전달, 결제 반영, 토스 결제 웹훅 수신, 정비 전산 흉내 화면 |
| `PROTOCOL.md` | 플러그인과 서버가 주고받는 메시지 규약 |
| `docs/` | 연동 방식·기술 정보 문서(pdf, docx) |

```
정비 전산(server/ 화면) --[담기]--> server/ <== WebSocket / HTTP 폴링 ==> plugin/ (토스 POS) --> 장바구니 → 결제
                                       ^
                                       └── 토스플레이스 결제 웹훅(승인·취소)
```

## 빠르게 해 보기 (POS 없이)

1. `server/`에서 `npm install` → `npm start` → 브라우저로 `http://127.0.0.1:8788` (정비 전산 흉내 화면)
2. 처음 실행할 때 콘솔에 시험 매장 토큰이 한 번 나옵니다.
3. 다른 창에서 `server/`의 `tools/fake-pos.mjs`로 가짜 POS를 붙입니다(사용법은 `server/README.md`).
4. 화면에서 작업을 만들고 [담기] → 가짜 POS가 받고 응답 → 결제 이벤트를 보내면 결제완료로 바뀝니다.

서버는 포트를 두 개 엽니다. `8787` 은 POS 플러그인과 토스 웹훅이 접속하는 창구이고, `8788` 은 인증이 없는 정비 전산 흉내 화면이라 이 PC(`127.0.0.1`)에서만 열립니다.

## 실제 토스 POS로 해 보기

1. `server/`의 `8787` 포트를 외부에서 접속되는 `https://` 주소로 엽니다(`8788` 은 넘기지 않습니다).
2. `plugin/`에서 `npm install` → `npm run release` → 저장소 루트의 `release/payment-example-plugin-1.0.0.zip`
3. 토스 개발자센터에 zip을 올리고, ACL에 서버 주소를 `https://<도메인>`, `wss://<도메인>`처럼 프로토콜까지 등록합니다.
4. 테스트 단말에서 플러그인 [설정]에 서버 주소와 매장 토큰을 넣습니다.
5. 토스 개발자센터 Open API 앱 → 웹훅에 `https://<도메인>/toss/webhook`(이벤트: 결제 승인·취소)을 등록하고, 시크릿과 Open API 키를 서버 환경변수에 넣습니다.

자세한 내용은 `plugin/README.md`, `server/README.md`를 보세요.

## 이 예제가 운영 코드가 아닌 부분

- 서버는 메모리에 저장합니다(재시작하면 작업·명령·결제 기록이 사라짐). 운영에서는 DB를 쓰세요.
- 정비 전산 흉내 화면은 인증이 없고 `127.0.0.1`의 별도 포트에서만 열립니다. 운영에서는 정비 전산의 실제 화면·기능으로 대체합니다.
- Open API 키 없이 서버를 띄우면(로컬 시험) POS 단말이 보낸 결제 알림을 확인 없이 그대로 반영합니다. 운영에서는 반드시 키를 넣어 토스에서 확인한 값으로 반영하게 하세요.
- 그 밖의 항목은 `server/README.md` 의 "운영 전환 시 바꿀 것"에 있습니다.
